# OpenWiki instructions

Hand-authored scope and priorities for this repository. OpenWiki reads this file on every run and
never rewrites it.

## What this repository is

`@banana.inc/zoho-desk-nodejs-sdk` is an ESM-only TypeScript SDK for the Zoho Desk REST API
(Node >= 18). Its defining characteristic is that the HTTP/transport layer is **generated** from
Zoho's OpenAPI spec by Microsoft Kiota, and a small hand-written layer wraps that generated code to
provide OAuth, data-center routing, error translation, logging, proxying and token persistence.

Roughly 99% of `src/` by line count is generated. The hand-written layer is ~3.5k LOC and is where
essentially every design decision lives.

## Audience

Contributors to this SDK, and coding agents working in this repository. Assume the reader knows
TypeScript and REST but knows nothing about Zoho Desk, Kiota, or this codebase's conventions.

Do not restate `README.md`. It already covers installation, quick start, and per-grant-type usage
snippets — link to it instead and spend the wiki's budget on *how the pieces fit together and why*,
which the README does not explain at all.

## Where to go deep

In descending priority:

1. **`src/auth/`** — the largest and subtlest hand-written area. Seven OAuth grant paths:
   refresh token, grant/authorization code, direct access token, client credentials, stored token
   by ID, PKCE, and device authorization. `oauth-token.ts` (~457 LOC) is the core;
   `device-auth.ts`, `authorization-url.ts`, `oauth-builder.ts`, `pkce.ts` (uses `node:crypto`),
   `token.ts` and `zoho-auth-provider.ts` surround it. Document how a token is acquired, cached,
   refreshed, and handed to the Kiota request adapter.
2. **`src/client/zoho-desk-client.ts`** — the unified facade. ~1,151 LOC, 127 lazy getters, one per
   generated module. It is itself generated by `scripts/generate-facade.ts` and carries a DO NOT
   EDIT header. Explain the lazy-instantiation pattern and how a caller gets from
   `createDeskClient()` to a specific module's request builders.
3. **`src/http/`** — `zoho-http-client.ts` (`createRequestAdapter`), plus two middlewares:
   `zoho-error-middleware.ts` (translates Zoho error payloads into `ZohoApiError`) and
   `empty-query-param-middleware.ts` (strips empty query params Zoho rejects). Document the
   middleware ordering and what each one changes about a request or response.
4. **The code generation pipeline** — `scripts/pull-and-generate.sh`, `scripts/generate-clients.sh`
   (Kiota via Docker, 8-way parallel), `scripts/bundle-oas.ts`, `scripts/oas-utils.ts`,
   `scripts/generate-facade.ts`. This is how the 126 modules come to exist and how a contributor
   regenerates them after an upstream spec change. It is not documented anywhere else.
5. **`src/dc/`** — `DataCenter` base plus US/EU/IN/AU/CA/CN/JP and `Environment`. Explain how a
   data center resolves to accounts and API base URLs.
6. **`src/store/`** — `TokenStore` interface and the CSV-backed `FileStore`. Cover the persistence
   contract and what implementing a custom store requires.
7. **`src/initializer/`**, **`src/config/`**, **`src/exception/`**, **`src/logger/`**,
   **`src/proxy/`**, **`src/index.ts`** — smaller, but each deserves a page.

`tests/` is in scope and is good evidence of intended behaviour; cite it when documenting contracts.

## Generated code

`src/generated/` is excluded via `.openwikiignore`, deliberately — do not treat its absence as an
oversight and do not try to enumerate its contents file by file.

One module, `src/generated/widget/`, is left readable as an exemplar. Use it to describe the
*shape* every generated module shares (`<module>ApiClient.ts`, `api/v1/...` request builders,
`models/index.ts`, `kiota-lock.json`). Derive the list of the other 125 modules from the getters in
`src/client/zoho-desk-client.ts` rather than from the filesystem. Do not attempt per-endpoint
reference documentation for generated modules — that is Zoho's API documentation's job, and the
wiki should link out rather than duplicate it.

- **A flowchart** for the codegen pipeline: upstream OAS -> bundle -> Kiota -> `src/generated/` ->
